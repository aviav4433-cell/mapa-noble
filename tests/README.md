## איך אצווה מוסיפה בדיקות

**כל אצווה מוסיפה. זה לא אופציונלי.** אצווה שנוגעת באזור קיים מוסיפה לקובץ
הקיים; אצווה שפותחת אזור חדש יוצרת `t0N-<נושא>.test.js`.

```js
module.exports = {
  title: 'שם שמופיע בפלט',
  needs: 'ui',          // 'ui' (jsdom) · 'server' (vm) · 'src' (קוד מקור בלבד)
  requires: ['go', 'allowedViews'],   // ⚠ ראה "מניעת ריקבון"
  tests: {
    'תיאור הבדיקה בעברית': (t, { w, srv, H }) => {
      H.login(w, 'מנהל', srv);
      w.go('orders');
      t.eq(w.VIEW, 'orders', 'הודעה שמסבירה מה נשבר');
    }
  }
};
```

**כלי הטענה:** `t.ok · t.no · t.eq · t.ne · t.has · t.hasNot · t.throws · t.fail`
כל אחד מקבל הודעה אחרונה — **כתוב בה מה נשבר, לא מה ציפית.**

**מה מקבלים ב-env:** `w` (חלון הדפדפן המדומה) · `srv` (הקשר השרת) · `H` (הרתמה).

## מניעת ריקבון — `requires`

הבעיה: בדיקה שמתייחסת לפונקציה שנמחקה מהקוד יכולה לעבור בשקט ולתת ביטחון שווא.

הפתרון: כל קובץ מצהיר ב-`requires` על הסמלים בקוד החי שהוא נשען עליהם.
לפני שהמריץ מריץ בדיקה אחת מהקובץ, הוא בודק שכולם קיימים. **סמל שנעלם ⇦
הקובץ כולו נכשל ברעש**, עם שם הסמל.

זה כבר עבד: `requires` תפס ש-`batchGet` ו-`buildPayroll` אינם פונקציות
גלובליות בשרת (השמות האמיתיים: `b58Prefetch`, `buildPayrollForMonth`).

## שתי מלכודות מקובעות ברתמה

1. **חובה לנטרל `setInterval`/`setTimeout` לפני `eval`.** בלי זה הריצה
   נתקעת לנצח — ה-polling של B58 מתזמן את עצמו מחדש.
2. **סריקת קוד מקור חייבת להסיר הערות קודם** (`H.stripComments`). בקוד יש
   ארבעה אזכורים של `history.back`/`history.go` — כולם בתוך הערות שמסבירות
   את האיסור. סורק תמים נכשל שקרית.

## R7 — אירועי DOM אמיתיים

ב-jsdom במצב `outside-only` מטפלי `on*` בתגית **אינם מקומפלים**. לכן:

```js
H.click(w, elem);            // מחבר את ה-onclick כמאזין ואז מדספאטץ' MouseEvent אמיתי
H.change(w, elem, 'ערך');    // אותו דבר ל-change
H.popstate(w, { mn:1, v:'orders' });
```

⛔ **קריאה ישירה ל-handler אינה בדיקה קבילה.**
